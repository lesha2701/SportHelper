# TeamFlow Sports — Design System (MASTER)

Дата: 2026-07-18. Редизайн палитры и типографики (заменяет предыдущую тёмную
тему на оранжевом акценте «Ignite Orange»). Источник — дизайн-система
"Kinetic Obsidian" (Electric Blue + Teal) из референса в Stitch, адаптированная
под существующую архитектуру токенов проекта.

**⚠️ Устарело:** цвета и радиусы ниже (разделы «Цвет» и «Форма») — это дизайн
до MBA-редизайна. Актуальная палитра — в разделе «MBA-редизайн (2026-08-17,
Phase 1 — ядро + Dashboard)» в конце файла.

## Направление

Тёмная, «технологичная» спортивная тема как основная (dark primary), с
полноценной светлой темой как альтернативой (переключатель в профиле, плюс
уважение `prefers-color-scheme` при первом запуске). Блочный стиль: чёткие
карточки на hairline-бордерах, умеренные (более чёткие, чем раньше) скругления,
без стекла/блюра — производительность в Telegram WebView и читаемость важнее
эффектных стилей. Дуотон-акцент: уверенный Electric Blue как первичный цвет +
приглушённый тил как вторичный (ссылки, второстепенные акценты) — даёт
современное, «финтех + спорт» ощущение, интуитивно понятное за счёт чёткой
иерархии цвета.

## Цвет

- `--color-bg-elevated: #151B2D`
- `--color-surface: #191F31` — карточки
- `--color-surface-alt: #23293C` — вложенные блоки, поля ввода
- `--color-border: rgba(180,195,255,0.09)`
- `--color-border-strong: rgba(180,195,255,0.16)`
- `--color-text: #E7EBFB`
- `--color-text-secondary: #9AA7C8`
- `--color-text-tertiary: #626D8A`
- `--color-primary: #2563EB` (Electric Blue) / hover `#3B82F6` / текст на нём `#FFFFFF`
- `--color-primary-glow: rgba(37,99,235,0.28)`
- `--color-accent-blue: #4CD9CB` (тил — ссылки, вторичные акценты)
- `--color-success: #34C778` / bg `rgba(52,199,120,0.14)`
- `--color-danger: #FF5A52` / bg `rgba(255,90,82,0.14)`
- `--color-warning: #F5A623` / bg `rgba(245,166,35,0.14)`

### Светлая тема
- `--color-bg: #F5F7FB`, `--color-surface: #FFFFFF`, `--color-surface-alt: #EEF1F7`
- `--color-border: #DFE4EE`, текст `#10162A` / `#5B6478` / `#8892A6`
- `--color-primary: #1D4ED8` (темнее для контраста на белом), текст на нём `#FFFFFF`
- `--color-accent-blue: #0D9488` (тёмный тил для контраста на светлом фоне)
- Семантика (success/danger/warning) — без изменений, уже были нейтральны к бренду

## Типографика

Два шрифта, разные роли (обновлено 2026-07-18 в рамках редизайна UI —
раньше был единый Montserrat). **Barlow Condensed** (`--font-display`,
подключён вес 600/700/800) — заголовки экранов, табы, нижняя навигация, кнопки,
бейджи, крупные цифры статистики: жирный, заглавные буквы, трекинг
`0.02–0.03em` для навигационных элементов, это и есть «спортивный» акцент.
**Montserrat** (`--font-body`) — весь читаемый текст: описания, метаданные,
значения полей. Заголовки (`h1-h3`, `.heading`) — с трекингом `-0.01em`
(крупные) или `0.02em` uppercase (масштабные section-заголовки типа
«Команды»/«Календарь»). Важно: uppercase применяется только к структурным
подпискам (навигация, табы, заголовки секций), а не к пользовательским данным
(названия команд, имена) — те остаются в исходном регистре.

## Форма

- Радиусы: `--radius-sm 6px`, `--radius-md 10px`, `--radius-lg 14px`, `--radius-pill 999px`
- Карточки: hairline-бордер + лёгкая тень (`--shadow-card`), без блюра
- Приподнятые/модальные поверхности получают лёгкое синее свечение
  (`--shadow-raised` содержит примесь `rgba(37,99,235,*)`)
- Активный таб/акцентный элемент — нижняя цветная полоса, а не заливка pill
- Иконки — только SVG (свой набор в `components/shared/Icon.tsx`), эмодзи убраны

## UI-паттерны (редизайн 2026-07-18)

Первый проход — 4 экрана-эталона (Команды, Карточка команды, Календарь,
нижняя навигация). Третий проход (см. ниже, тот же день) раскатал те же
паттерны на все остальные экраны приложения. Переиспользуемые паттерны в
`teams.module.css` (расшарен между Teams/TeamDetail/Calendar/Matches/Tasks/
Library/MyTeams — то есть практически всеми списками карточек в приложении):

- **Аватар команды** (`.teamAvatar`) — лого команды, если есть, иначе первая
  буква названия на тонированном фоне `--color-primary-glow`. Даёт карточкам
  визуальный якорь вместо чистого текста.
- **Плитки статистики** (`.statGrid`/`.statTile`/`.statValue`/`.statLabel`) —
  2-колоночная сетка крупных цифр (Barlow Condensed, `--color-primary`) для
  показателей, которые реально есть в данных (участники, роль). Не выдумывать
  метрики, которых нет в API.
- **Цветная линия событий календаря** (`.eventRow` + CSS-переменная
  `--event-color`) — левая полоса 3px, цвет зависит от типа события:
  тренировка → `--color-primary`, матч → `--color-accent-blue`, дедлайн
  задания → `--color-warning`. Ускоряет визуальное сканирование списка без
  доп. текста.
- **Тактильная обратная связь** — нижняя навигация и табы получили
  `scale(0.94–0.97)` на `:active` (важнее hover в Telegram WebView, где
  основной ввод — тач).

## Правки по итогам обратной связи (2026-07-18, файл «дизайн правки.docx»)

Второй проход — не только визуальный, но и структурный/функциональный, по
конкретным замечаниям пользователя со скриншотами:

- **Навигация внутри команды** (`TeamDetailScreen`) — таб-бар перегружался
  (7 вкладок обрезались). Оставлены только Обзор/Тренировки/Задания/Матчи;
  Состав/Статистика/Настройки стали кнопками-строками (новый паттерн
  `.navRow`/`.navRowIcon`/`.navRowLabel`/`.navRowChevron` в
  `teams.module.css`) на вкладке Обзор. Использовать этот паттерн для любой
  «вложенной» навигации, которая не помещается в горизонтальный таб-бар.
- **Календарь**: вкладка «Список» теперь показывает ближайшую непрошедшую
  тренировку первой (future ASC, затем past DESC — см.
  `compareUpcomingFirst` в `CalendarScreen.tsx`), а просроченные тренировки
  вынесены в отдельную вкладку «Просрочено» вместо подмешивания в общий
  список.
- **Чек-лист упражнений** (`TrainingDetail.tsx`) — свободный текст описания
  личной тренировки (если он в распознаваемом формате, см.
  `parseExerciseChecklist`) рендерится как чек-бокс-список
  (`.checklistItem`/`.checklistCheckbox`/`.checklistLabel[Done]` в
  `training.module.css`), а не сплошным абзацем. Отметки — только на
  клиенте (не сохраняются), это осознанное ограничение: в БД нет поля для
  прогресса по упражнениям.
- **Таймер тренировки** (`TrainingSessionScreen.tsx`) — кнопка «Начать
  тренировку» на карточке чек-листа. Для круговой тренировки (когда в
  описании есть блок «Кругов: N · Отдых: R сек», который добавляется через
  новые поля в `TrainingForm.tsx`) — обратный отсчёт по каждому упражнению
  и отдых между подходами/кругами. Для тренировки «на повторения» — ручное
  пошаговое прохождение (нет данных о длительности повторений, поэтому без
  таймера). Полностью client-side, без изменений в БД — осознанный выбор,
  чтобы не делать схемную миграцию в рамках дизайн-правок; прогресс сессии
  не переживает перезагрузку страницы.
- **Файловый пикер** (`components/shared/FilePicker.tsx` +
  `FilePicker.module.css`) — заменяет голые `<input type="file">` (логотип
  команды, фото/видео упражнения, отчёта, задания) на единый стилизованный
  компонент с иконкой и подсказкой формата. Использовать его для любого
  нового места загрузки файла вместо голого `<input>`.
- **Иллюстрации пустых/ошибочных состояний** (`components/shared/illustrations.tsx`)
  — три крупные SVG-иллюстрации (`EmptyIllustration`/`ErrorIllustration`/
  `ForbiddenIllustration`) в том же линейном стиле, что и `Icon.tsx`
  (`currentColor`, скруглённые концы), подключены в `StateScreen.tsx` вместо
  мелкой иконки — это покрывает пустые/ошибочные состояния сразу во всём
  приложении, так как `StateScreen` общий для ~50 экранов.
- **Помощь** — экран `HelpScreen.tsx`, открывается кнопкой «Помощь» в
  профиле, описывает разделы приложения простым языком.

## Полный раскат паттернов (2026-07-18, третий проход)

Те же паттерны, что на 4 экранах-эталонах, применены на всех оставшихся
экранах. Правило по каждому паттерну — где он применялся и где сознательно
нет:

- **`.teamAvatar`** — добавлен в `MyTeamsSection` (та же карточка команды,
  что в `TeamsScreen`) и как именной инициал в `PlayerProfileView`. Для
  списков без «именованной сущности с лого» (упражнения/планы/шаблоны
  заданий) используется тот же слот `.teamAvatar`, но с фиксированной
  иконкой по типу контента (гантель/планшет/флаг) — не выдумывать
  категории, которых нет в данных.
- **`--event-color` на `.teamCard`** — граница `.teamCard` получила
  `border-left: 3px solid var(--event-color, var(--color-border))`
  (обратно совместимо: без переменной выглядит как раньше). Применён к
  матчам (по `result`/`status`), заданиям (по «худшему» статусу среди
  исполнителей — см. `STATUS_URGENCY` в `TeamTasksTab.tsx`) и тренировкам
  команды (просрочена/завершена/отменена/запланирована).
- **`.statGrid`/`.statTile`** — раскатан на все экраны с реальными
  числовыми показателями: счёт матча (`MatchDetail`), статистика игрока и
  команды (`PlayerStatsScreen`, `TeamStatsTab` — включая победы/ничьи/
  поражения матчей, победы подсвечены `--color-success`, поражения
  `--color-danger`).
- **`.pageHeading`** (новый класс в `profile.module.css`, зеркалит
  `.heading` из `teams.module.css`: 24px/800/uppercase) — применён к
  заголовкам форм и структурных экранов (создание/редактирование команды,
  тренировки, задания, матча, упражнения, плана, шаблона; Onboarding;
  «Статистика»; экраны приглашения). **Не** применять к заголовкам, где
  интерполируется имя/название сущности из данных (`team.name`,
  `player.fullName`, `exercise.name` и т.п.) — те остаются на `.title` в
  исходном регистре, это осознанное правило, а не недосмотр.
- **`.fieldSectionLabel`** — сгруппировал 9 полей `PlayerProfileForm` в
  три секции (Основное/Физические данные/Спорт/Цели). Использовать для
  любой формы с 6+ полями без естественной группировки; формы короче
  (5 полей и меньше, напр. `CoachProfileForm`) не нуждаются.

## Движение

Умеренно, без изменений: transition 150-220ms ease-out на interactive states;
drag-n-drop — только там, где порядок имеет смысл (список упражнений в плане
тренировки — `PlanForm`), с `scale(1.02)` + усиленной тенью на «поднятом»
элементе. `prefers-reduced-motion` уважается глобально.

## Компоненты, которые меняются централизованно

Все ~50 экранов держатся всего на 8 CSS-модулях (`index.css` + 7
`*.module.css` в teams/library/trainings/profile + StateScreen/ConfirmModal/
BottomNav) — смена токенов в них перекрашивает всё приложение без
переписывания логики компонентов.

## MBA-редизайн (2026-08-17, Phase 1 — ядро + Dashboard)

Полная замена палитры и точечная правка формы под айдентику баскетбольного
клуба МБА — см. `docs/superpowers/specs/2026-08-17-mba-redesign-design.md`
для полного обоснования. Итог Phase 1:

- **Тема**: светлая стала основной (было — тёмная); тёмная осталась
  полноценной вторичной темой, не заглушкой. Переключение по-прежнему в
  `ThemeContext.tsx` / кнопка в профиле.
- **Цвет**: `--color-primary` — MBA Red (`#D91E2B` светлая / `#FF3B3F`
  тёмная), `--color-accent-blue` перекрашен в коралловый (был тил/бирюза;
  имя переменной сохранено, чтобы не трогать 4 файла, где он используется).
  `--color-danger` теперь оранжево-красный, отдельный от бренда, чтобы не
  путать ошибки с акцентом. `--color-primary-glow` теперь светло-розовая
  заливка (была синим свечением) — имя тоже сохранено (5 мест использования
  не тронуты).
- **Форма**: радиусы уменьшены (`--radius-lg` 14→12px, `--radius-md`
  10→8px, `--radius-sm` 6→4px) — более чёткая геометрия, pill остался
  только у бейджей/переключателей.
- **Типографика**: `.heading`/`.pageHeading` выросли с 24px до 28px;
  `.statValue` и новый `StatTile` получили `tabular-nums`.
- **Новые shared-примитивы**: `components/shared/Ornament.tsx`
  (волнообразные полосы, параметры `tone`/`intensity` — используется только
  в hero-блоках, никогда за плотными данными) и
  `components/shared/StatTile.tsx` (крупная KPI-цифра 40px, отдельно от
  существующего мелкого `.statGrid`/`.statValue` в `teams.module.css` —
  оба паттерна остаются, не путать роли).
- **Новый экран**: `components/dashboard/` (`DashboardScreen` — роутер по
  `activeMode`, `CoachDashboard`, `PlayerDashboard`) — первая вкладка
  «Главная» у обеих ролей, собрана из уже существующих
  `GET /api/calendar`, `GET /api/teams/{id}/stats`,
  `GET /api/players/{id}/stats` — без изменений backend.
