# Push-уведомления

Push — копия уведомления, которое уже лежит в ленте («колокольчике»): сервер при отправке уведомления дополнительно шлёт его на телефоны
получателя. Лента остаётся главным местом, где всё видно; push ничего не заменяет и ни от чего не зависит (ни от Telegram, ни от почты).

## Как это устроено

1. Приложение просит у человека разрешение и получает от системы **токен устройства**: на iPhone — токен APNs, на Android — токен FCM.
2. `PUT /api/devices` `{platform: "ios"|"android", token, app_version?}` — приложение сообщает токен серверу после входа и каждый раз,
   когда система выдаёт новый. Повторный вызов с тем же токеном только обновляет запись (идемпотентно). Токен уникален: если на этом
   телефоне вошёл другой человек, запись переходит к нему.
3. `POST /api/devices/remove` `{token}` — при выходе, пока сессия ещё жива: телефон перестаёт получать уведомления выходящего.
   Чужой токен удалить нельзя (удаляется только запись самого пользователя).
4. Фоновая задача (`services/background.py`), отправляя очередное уведомление, шлёт push на все устройства получателя
   (`services/push.py` → `integrations/push.py`). Только при первой попытке: повтор отправки в Telegram не звонит в телефон второй раз.
   Выключенная в настройках категория уведомлений не отправляется никуда, в том числе и push.
5. Провайдер сказал, что токен мёртв (приложение удалено, токен заменён) — запись удаляется. Любая другая ошибка (сеть, наши ключи)
   только пишется в лог: push — копия, она не повторяется и не блокирует остальное.

Что внутри push: заголовок и текст уведомления и поля `notification_id`, `category`, `entity_type`, `entity_id` — по ним приложение при
нажатии открывает нужный экран (те же пары, что у кнопки в Telegram и у ленты).

## Что нужно настроить на сервере

Каждая сторона включается наличием своих ключей; без них ничего не отправляется и ничего не ломается (лента работает).

| Переменная | Что это |
|---|---|
| `APNS_KEY_ID`, `APNS_TEAM_ID` | идентификатор ключа и команды в аккаунте разработчика Apple |
| `APNS_BUNDLE_ID` | `ru.sportarenaglobal.app` |
| `APNS_PRIVATE_KEY` | содержимое файла ключа `.p8` (текст PEM; переводы строк можно записать как `\n`) |
| `APNS_SANDBOX` | `true` для сборок из Xcode (токены песочницы), `false` для TestFlight и App Store |
| `FCM_SERVICE_ACCOUNT_JSON` | JSON сервисного аккаунта проекта Firebase (Project settings → Service accounts → Generate new private key), одной строкой |

Отправка идёт напрямую в APNs (HTTP/2, подпись ES256) и FCM HTTP v1 (OAuth по подписанному JWT) — отдельных библиотек не нужно, подпись
делает `cryptography`, для HTTP/2 в `requirements.txt` стоит `httpx[http2]`.

## Что нужно для сборок

**iPhone.** В аккаунте разработчика Apple создать ключ APNs (Keys → «Apple Push Notifications service»), включить возможность Push
Notifications для `ru.sportarenaglobal.app`. В `ios/project.yml` уже есть `aps-environment` (при подписи для App Store Xcode сам
меняет его на production). Push не работает в симуляторе без настройки и не работает без платного аккаунта разработчика.

**Android.** Создать проект Firebase с приложением `ru.sportarena.app`, скачать `google-services.json`, положить в `mobile/` и указать в
`app.json`: `"android": { "googleServicesFile": "./google-services.json" }`. Файл не коммитить (ключи проекта). Push не работает в Expo Go:
нужна собственная сборка (`eas build` или `expo run:android`). Канал уведомлений `default` приложение создаёт само.

## Проверка

Сервер: `backend/tests/test_push.py` (запросы к APNs и FCM на подставном транспорте, рассылка по устройствам, удаление мёртвых токенов,
маршруты). Клиенты: `mobile/src/shared/lib/pushData.test.ts`, `ios/Tests/SportArenaKitTests/PushTests.swift`.
Вручную: войти на телефоне (токен появится в таблице `push_devices`), создать уведомление, которое должно прийти сразу (например,
заявка на тренировку тренеру), и дождаться его — задача фоновая, проходит раз в несколько секунд.
