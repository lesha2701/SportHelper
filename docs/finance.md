# Финансовый контур SportArena: платежи, баланс тренера, выводы

> Статус: разрабатывается поэтапно, все возможности **выключены по умолчанию** (см. «Флаги»). Реальных платежей и выплат при
> разработке не выполнялось. Юридическая и налоговая модель не подтверждена — см. раздел «Что нужно подтвердить».

## A. Аудит и принятые решения

**Что уже было:** бронирования (`bookings`: статусы pending/confirmed/declined/expired/cancelled, цена и валюта **фиксируются в
момент заявки** и не меняются при правке объявления), подтверждение тренером создаёт тренировку (`trainings`); отмена брони
пользователем не реализована (статус `cancelled` никем не ставится), тренировку можно отменить (`trainings.status='cancelled'`);
факт проведения фиксирует тренер кнопкой «проведена» (`trainings.status='completed'`) — **надёжного независимого подтверждения нет**.
Двойное бронирование слота закрыто частичным уникальным индексом. Уведомления: очередь `notifications` + фоновый цикл (это
transactional outbox: строка пишется в той же транзакции, доставка отдельно, сбой Telegram/SMTP финансы не блокирует). Админка:
`ADMIN_EMAILS` + MFA + `require_admin_write`/`require_admin_recent_mfa` + журнал `admin_audit_log` (append-only). Шифрование:
Fernet (как у TOTP). Старого платёжного кода не было (платёжный контур этой итерации — первый).

**Деньги** хранятся целыми **копейками** (`BIGINT`), без float. Комиссия платформы = `gross × percent / 100`, округление
**half-up до копейки** (одно правило, `app/services/money.py`). Процент и суммы фиксируются в `payments` / `trainer_earnings`
**на момент создания** обязательства и никогда не пересчитываются при смене конфигурации.

### Сущности

| Таблица | Назначение |
|---|---|
| `payments` | обязательство оплатить бронь (1:1 с бронью): сумма, комиссия, доля тренера — снимок на момент создания |
| `payment_attempts` | каждая попытка оплаты в ЮKassa (id платежа, ключ идемпотентности, статус); не более одной открытой и одной успешной на платёж |
| `payment_events` | журнал входящих уведомлений/сверок (диагностика, дедупликация не нужна: обработка идемпотентна) |
| `payment_incidents` | расхождения и инциденты (двойная оплата, несовпадение суммы, оплаченная бронь отменена и т.д.) |
| `ledger_accounts` / `ledger_transactions` / `ledger_entries` | неизменяемый журнал двойной записи; остаток счёта ведёт триггер, `CHECK (balance >= 0)` защищает от отрицательного остатка при гонках |
| `trainer_earnings` | начисление тренеру по конкретной оплате: pending → available (held / reversed) |
| `withdrawal_requests` / `withdrawal_events` | заявки на вывод и неизменяемая история их статусов; реквизиты зашифрованы |
| `refunds` | возвраты (через ЮKassa), с разбивкой на комиссию платформы и долю тренера |

### Счета журнала (двойная запись)

`provider_receivable` (актив: деньги, которые держит для нас ЮKassa) · `platform_revenue` (комиссия SportArena) ·
по тренеру: `trainer_pending` (ожидает) · `trainer_available` (доступно) · `trainer_reserved` (зарезервировано под вывод) ·
`trainer_debt` (актив: долг тренера после возврата, когда деньги уже выплачены/зарезервированы) · `payouts_external` (выплачено).

### Движение денег (пример: тренировка 2 000 ₽, комиссия 10%)

1. **Оплата подтверждена** (ЮKassa сообщила + мы перечитали платёж + сошлись id/сумма/валюта):
   Дт `provider_receivable` 2000 / Кт `trainer_pending` 1800 + Кт `platform_revenue` 200.
2. **Тренировка проведена** (тренер отметил) → начисление **готово к проверке**; **выпуск** в доступные: `trainer_pending → trainer_available` 1800
   (по умолчанию — вручную финансовым админом, т.к. независимого подтверждения нет; режим `auto_after_hold` — через `EARNING_HOLD_HOURS`).
3. **Заявка на вывод** (от `TRAINER_MIN_WITHDRAWAL_RUB`): `trainer_available → trainer_reserved` атомарно, под блокировкой счёта.
4. **Выплата выполнена вручную** в банке, админ зафиксировал банковский id: `trainer_reserved → payouts_external`.
   Отклонение/отмена до перевода: `trainer_reserved → trainer_available`.
5. **Возврат игроку** (инициирует финансовый админ, исполняет ЮKassa, учитывается по `refund.succeeded` **после перечитывания**):
   Кт `provider_receivable` / Дт `platform_revenue` (доля комиссии, пропорционально) / Дт доля тренера: сначала `trainer_pending`,
   затем `trainer_available`, остаток — `trainer_debt` (долг, виден админам, автоматически не списывается).

### Политики, принятые «по умолчанию» (меняются конфигом, согласуйте)

* Комиссия SportArena **возвращается пропорционально** при возврате (`REFUND_RETURNS_COMMISSION=true`).
* Комиссия **ЮKassa** — отдельный расход платформы, с баланса тренера **не удерживается**; в отчётах показывается отдельно (ввод фактических сумм — вручную, из отчётов ЮKassa).
* Тренировка отменена/не состоялась после оплаты → платёж помечается инцидентом «нужна проверка возврата»; **автоматических возвратов нет**.
* Спорные начисления можно «заморозить» (`held`) — они не выпускаются.

## Флаги (все false по умолчанию)

`YOOKASSA_ENABLED`, `TRAINER_BALANCE_ENABLED`, `TRAINER_WITHDRAWALS_ENABLED`, `TRAINER_PAYOUT_CONFIRMATION_ENABLED`
(подтверждение **реальных** выплат в админке; пока выключено — подтвердить выплату нельзя). Подробности — в «Настройках» ниже.
