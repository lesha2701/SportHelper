# Ручное тестирование регистрации и входа

Проходится один раз на реальном окружении перед открытием сайта (и после смены почтового сервиса или домена). Нужны: сайт на HTTPS,
настроенный SMTP, **два** реальных почтовых ящика (A — «владелец», B — «чужой») и два браузера или обычный + приватное окно.
Логи backend: `docker compose logs -f backend` (ссылки и пароли в них не попадают).

Условные обозначения: ✅ ожидаемый результат · 🔍 что проверить в DevTools (F12).

## 0. Подготовка
1. Откройте `https://ДОМЕН` — главная страница, **замок HTTPS** без предупреждений; `http://ДОМЕН` перенаправляет на https.
2. 🔍 Network → любой запрос к домену → заголовки ответа: `Strict-Transport-Security`, `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`. Console — без ошибок CSP (красных «Refused to…»).
3. `https://ДОМЕН/docs` и `/openapi.json` → ✅ 404 (Swagger выключен).

## 1. Регистрация
1. «Регистрация» → пустая форма → «Зарегистрироваться» → ✅ ошибки у полей (имя, email, пароль, согласие), запрос на сервер не уходит.
2. Заполните: имя, **email A**, пароль из 12+ символов (например фраза из трёх слов), повтор, галочка согласия, роль «Я игрок». Отправьте.
3. ✅ Экран «Проверьте почту» с адресом A; кнопка «Отправить ещё раз» активна, после нажатия — пауза 60 с.
4. ✅ На ящик A за ≤ 1 минуты пришло письмо «Подтвердите email» (не в «Спам»; если в «Спам» — проверьте SPF/DKIM/DMARC). Отправитель — ваш `SMTP_FROM`.
5. Повторите регистрацию с тем же email A → ✅ «Аккаунт с таким email уже есть» только если он уже подтверждён; до подтверждения повторная регистрация заменяет попытку и приходит **новое** письмо (старая ссылка перестаёт работать).
6. Слабые пароли: `password1234`, `aaaaaaaaaaaa`, 11 символов, пароль = email → ✅ отклонены с понятным текстом.

## 2. Подтверждение email (и защита от «чужой» регистрации)
1. Откройте ссылку из письма. ✅ Страница «Подтвердите email» показывает **замаскированный** адрес (`a***e@…`) и просит пароль. 🔍 В адресе есть `?token=…`, письмо не логирует его нигде.
2. Введите **неверный** пароль → ✅ «Пароль не совпадает…», аккаунт не активирован, ссылка осталась рабочей, появилась подсказка «задайте новый пароль».
3. Введите **верный** пароль → ✅ «Email подтверждён», кнопка «Войти».
4. Откройте ту же ссылку ещё раз → ✅ «Ссылка не сработала» + форма «Прислать новую ссылку».
5. **Сценарий «чужой email»:** в приватном окне зарегистрируйте email **B** с паролем `чужой пароль для проверки`. В ящике B откройте ссылку → введите произвольный пароль → ✅ отказ → нажмите «Я не регистрировался(-ась)…», задайте **свой** новый пароль → ✅ подтверждено; войти со старым «чужим» паролем нельзя, с новым — можно.
6. Ссылка с истёкшим сроком (24 ч) — проверить можно, изменив на тестовой базе `expires_at`; на проде достаточно автотестов.

## 3. Вход
1. «Войти» с неверным паролем → ✅ «Неверный email или пароль» (то же сообщение для несуществующего адреса).
2. С верным → ✅ главная приложения (при первом входе — знакомство). 🔍 Application → Cookies: `__Host-sag_session` с флагами **HttpOnly ✓, Secure ✓, SameSite=Lax, Path=/**, без Domain. 🔍 Application → Local/Session Storage: **нет** токенов (только `tf-theme`). 🔍 В консоли `document.cookie` не содержит сессию.
3. Обновите страницу (F5) и закройте/откройте вкладку → ✅ вы остались в аккаунте.
4. Пять неверных паролей подряд → ✅ «Слишком много неудачных попыток», верный пароль тоже временно отклоняется (15 мин); через 15 мин вход работает.
5. Регистрация без подтверждения, затем вход → ✅ «Подтвердите email» со ссылкой «Отправить письмо ещё раз».

## 4. Запись «гостем» (возврат к цели)
1. Выйдите. Откройте «Тренеры» (без аккаунта) → профиль → «Записаться» → ✅ страница входа с пояснением «Войдите… чтобы записаться».
2. Войдите (или зарегистрируйтесь и подтвердите почту ссылкой из письма) → ✅ сразу форма записи именно этого объявления.

## 5. Восстановление пароля
1. «Забыли пароль?» → email **A** → ✅ «Если аккаунт с таким адресом существует, мы отправили письмо». Для **несуществующего** адреса — тот же текст, письмо не приходит.
2. Письмо «Восстановление пароля» → ссылка → новый пароль (+повтор) → ✅ «Пароль изменён».
3. Старые сессии (другой браузер) → ✅ разлогинены; старый пароль не подходит; новый — подходит. На ящик пришло уведомление «Пароль изменён».
4. Откройте ссылку ещё раз → ✅ «Ссылка не работает» + «Запросить новую». Ссылка живёт 30 минут.
5. Запросите восстановление 4 раза подряд для одного адреса → ✅ после третьего письма лимит (429), писем больше нет.

## 6. Аккаунт и безопасность и выход
1. Профиль → Настройки → «Аккаунт и безопасность»: виден email со статусом «подтверждён», список устройств с пометкой «это устройство».
2. Войдите вторым браузером → в списке два устройства → «Завершить» напротив второго → ✅ второй браузер при следующем действии возвращается к входу («Сессия закончилась»).
3. «Сменить пароль» с неверным текущим → ошибка; с верным → ✅ другие устройства разлогинены, это — нет.
4. «Изменить email» на ящик B (нужен пароль) → ✅ письмо на B со ссылкой и **предупреждение на A**; до перехода по ссылке адрес прежний; после — новый.
5. «Выйти из аккаунта» → ✅ главная публичная страница; 🔍 cookie сессии удалена; кнопка «Назад» не возвращает в приложение.
6. «Выйти на всех устройствах» → ✅ подтверждение, затем выход везде.
7. «Запросить удаление» (нужен пароль) → ✅ письмо, плашка с датой и «Отменить удаление»; отмените.

## 7. Telegram (если бот включён)
1. Старый Telegram-аккаунт: `/start` у бота → кнопка «Перенести аккаунт на email» → на сайте email + пароль → письмо → подтверждение → вход → ✅ те же команды, тренировки и профиль.
2. Настройки → «Подключить Telegram» → в боте видно **маскированный email аккаунта** → «Подключить уведомления» → ✅ «Telegram подключён». Один Telegram нельзя подключить ко второму аккаунту.

## 8. Администратор (после `ADMIN_EMAILS`)
1. Войдите администратором → «Аккаунт и безопасность» → «Двухфакторная защита» → настройте TOTP, сохраните резервные коды.
2. `GET /api/admin/users` (через DevTools Console: `fetch('/api/admin/users').then(r=>r.json())`) в **новом** браузере без ввода кода → ✅ `mfa_required`; после ввода кода — список. Обычный пользователь → `403`.

## 9. Что смотреть в логах после прохода
`docker compose logs backend | grep -iE "token|password|sag_session"` → ✅ только `[redacted]` или пусто; `grep teamflow.email` — отправки без ссылок.
