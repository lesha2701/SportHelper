# Оплата тренировок (ЮKassa)

Полная картина денег (комиссия, баланс тренера, выводы, возвраты, администрирование) — в [finance.md](finance.md). Здесь — только оплата.

## Как это работает для людей

1. Игрок выбирает тренера и отправляет заявку на бронь.
2. Тренер подтверждает её — **только после этого** у игрока в «Мои брони» появляется кнопка **«Оплатить эту тренировку»**
   (если у тренировки есть цена и оплата включена). До подтверждения тренером платить нельзя, статус — «Ожидает подтверждения тренера».
3. Кнопка открывает страницу оплаты ЮKassa. Карточные данные вводятся только там — сайт их не получает.
4. После оплаты игрок возвращается на `/payments/return`. Эта страница **ничему не верит из адреса**: она спрашивает у сервера,
   чем кончился платёж, и показывает только то, что сервер подтвердил: «Оплата прошла» / «Оплата обрабатывается» / «Платёж отменён».

Статусы оплаты на сайте: Ожидает подтверждения тренера · Ожидает оплаты · Оплата обрабатывается · Оплачено · Платёж отменён ·
Ошибка оплаты · Возврат обрабатывается · Возвращено.

Под кнопкой стоит текст: «Нажимая «Оплатить», вы заключаете договор с Тренером на Типовых условиях оказания услуг тренером.
Платформа принимает оплату как агент Тренера и не является исполнителем услуги.» Само нажатие записывается как принятие
Типовых условий (см. [legal.md](legal.md)); принятие привязано к конкретной брони.

## Настройка

Переменные — в `.env` на сервере (секретный ключ нигде не печатается и в браузер не передаётся). Полный перечень — в таблице
«Настройки» в [finance.md](finance.md). Для оплаты нужны: `YOOKASSA_ENABLED=true`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`;
при необходимости `YOOKASSA_RETURN_URL`, `YOOKASSA_SEND_RECEIPT`, `YOOKASSA_VAT_CODE`.
Сайт узнаёт, включена ли оплата, из `GET /api/features` (фронтенд пересобирать не нужно). После изменения `.env`:

```bash
docker compose up -d --force-recreate backend
```

### HTTP-уведомления (webhook)

В кабинете ЮKassa (Интеграция → HTTP-уведомления) укажите адрес `https://<ваш-сайт>/api/payments/yookassa/webhook`
и события `payment.succeeded`, `payment.canceled`, `payment.waiting_for_capture`, `refund.succeeded`.
Адрес должен открываться по HTTPS (порт 443, действующий сертификат). Ответ сайта: `200` — принято; `502` — сайт не смог
проверить платёж в ЮKassa, **ЮKassa повторит уведомление** (до 24 часов); `403` — запрос не с адресов ЮKassa; `400`/`413` — мусор.

## Как защищена оплата

- **Сумму сайт берёт из брони** (цена на момент заявки), браузер сумму не присылает. Только RUB. Сумма, комиссия и доля тренера
  фиксируются в `payments` при создании и не пересчитываются.
- Платить может только игрок этой брони, только за **подтверждённую** тренером запись, пока тренировка не прошла и не отменена.
- **Попытки отделены от платежа**: у одного платежа может быть несколько попыток (`payment_attempts`), но в БД (частичные
  уникальные индексы) — не более одной открытой и не более одной успешной. Запрос в ЮKassa идёт с ключом идемпотентности
  (`Idempotence-Key`), а сетевой вызов выполняется **вне транзакции БД**.
- **Успех принимается только после того, как сайт сам перечитал платёж из API ЮKassa** своими ключами и сошлись id, статус
  `succeeded`/`paid`, валюта, сумма и бронь в `metadata`. Тело уведомления не доверенное: оно только называет платёж.
  Поддельный webhook или поддельный адрес возврата ничего не оплатит.
- Слои защиты webhook: диапазоны адресов ЮKassa (`YOOKASSA_WEBHOOK_IP_CHECK`, ограничение размера тела) → перечитывание платежа →
  сверка суммы/валюты/брони → идемпотентная обработка (повтор уведомления ничего не начислит второй раз).
- **Фоновая сверка** (`services/reconcile.py`): ограниченными пачками (`PAYMENT_RECONCILE_BATCH`) проверяет незавершённые
  попытки моложе `PAYMENT_RECONCILE_MAX_AGE_HOURS`, с растущими паузами; недосозданные платежи повторяет с тем же ключом
  идемпотентности (в пределах 23 часов, потом попытка закрывается и заводится инцидент). Подвисший платёж не теряется, даже если
  ни webhook, ни возврат игрока не дошли.
- **Двойная реальная оплата** одной брони (две попытки обе прошли) не начисляется дважды: вторая помечается `duplicate_paid`,
  заводится инцидент, финансовый администратор делает контролируемый возврат.
- Номер карты и CVC сайт не получает и не хранит.
