# Блог (статьи тренеров и игроков)

Проект и решения: [docs/superpowers/specs/2026-11-23-blog-design.md](superpowers/specs/2026-11-23-blog-design.md).
Блог реализован на сервере, сайте, iPhone и Android. Этот документ описывает используемый клиентами API.
Точные схемы — в `docs/openapi.json` (теги `blog`, `admin-blog`).

## Что видит человек
* **Блок на главной** — одна «лучшая статья» для вида спорта человека (`GET /api/blog/featured`); `null` — блока нет.
  Нажатие открывает статью, под ней ссылка «Все статьи» на ленту.
* **Лента «Статьи»** — вкладки «Все» / «Мои» / «Сохранённые»; на «Все» фильтр по виду спорта и порядок «Новые / Популярные»; кнопка «Написать».
* **Статья** — до 3 фото каруселью, заголовок, автор, текст, карточка объявления с «Записаться» (если автор — тренер и прикрепил),
  лайк, комментарии, «три точки».
* **Автор** — тренер: имя, опыт, ссылка на профиль и объявления; игрок: профиль открыт только если сам разрешил, иначе видно лишь имя.

Статьи, лента, комментарии и карточка автора читаются **без входа** (в приложении сессия есть всегда). Лайк, комментарий, сохранение,
скрытие, жалоба, просмотр, написание — только после входа.

## Формат текста
Статья — список блоков:

```json
{"type": "paragraph|heading|quote", "text": "Это **важно** и *нужно*"}
{"type": "list", "items": ["пункт", "ещё пункт"]}
```
В тексте значимы только `**жирный**` и `*курсив*` (так же, как на сайте: `/\*\*(.+?)\*\*|\*(.+?)\*/`; непарный маркер остаётся как набран).
Показывать **как текст, не как HTML**: больше ничего не разбирается. Длина считается без маркеров. Фото — не блоки, а карусель статьи
(`image_ids`, порядок как в списке).

Редактор: поле на блок, кнопки «Ж» и «К», оборачивающие выделение в `**` / `*`, предпросмотр. У списка — один пункт на строку.

## API
Чтение:
* `GET /api/blog/posts?sport=&author_id=&sort=new|popular&limit=20&offset=0` → `{total, limit, offset, items: [PostCard]}`.
* `GET /api/blog/sports` → список видов спорта (тот же, что в профиле; в статье допустимы только они).
* `GET /api/blog/featured` → `PostCard | null`.
* `GET /api/blog/mine` → свои статьи любого статуса (`MyPost`), `GET /api/blog/bookmarks` → сохранённые (страницей).
* `GET /api/blog/posts/{id}` → `Post` (чужую неопубликованную видит только автор и админ — иначе 404).
* `GET /api/blog/posts/{id}/comments` → комментарии по времени.
* `GET /api/blog/authors/{id}` → карточка автора (`profile_open`, `posts_count`, `muted_by_me`).

Запись (всё — для вошедшего):
* `POST /api/blog/images` — multipart, поле `file` (jpeg/png/webp) → `{file_id}`. Фото ничьё, пока статья не назвала его в `image_ids`.
  Прислать сжатое (iPhone шлёт JPEG до 2048 px). Не более 30 в час.
* `POST /api/blog/posts` и `PUT /api/blog/posts/{id}` — тело `{title, sport, blocks, image_ids, listing_id, submit}` → `Post`.
  `submit: false` — черновик, `true` — отправить на проверку. Не более 10 отправок в сутки.
* `DELETE /api/blog/posts/{id}` — автор или админ.
* `POST /api/blog/posts/{id}/view` — засчитать просмотр (204). Один раз в сутки на человека, автор себя не считает; **анонимы не считаются**. Ошибку можно игнорировать.
* `PUT|DELETE /api/blog/posts/{id}/like` → `{liked, likes_count}`.
* `PUT|DELETE /api/blog/posts/{id}/bookmark`, `.../hide` — сохранить, скрыть статью (для себя), 204.
* `PUT|DELETE /api/blog/authors/{id}/mute` — «Скрыть автора» (для себя), 204.
* `POST /api/blog/posts/{id}/comments` `{body}` (до 1000 знаков, 20 в час) → `Comment`; `DELETE /api/blog/comments/{id}` — свой (или админ).
* `GET|PUT /api/blog/settings` — `{show_profile_in_posts}` (только у игроков): открывать ли свой профиль из статей. По умолчанию выключено.

Жалобы — обычный `POST /api/complaints` с новыми целями `post` и `post_comment` и новой причиной `advertising` («Реклама»).
Блокировка человека скрывает его статьи и комментарии в обе стороны.

## Правила и проверки
* Заголовок 3–120 знаков, текст 30–10 000 знаков (без маркеров), до 60 блоков, до 3 фото, вид спорта из списка.
* **Контакты** (телефоны, почта, ссылки, @ники) в статье не принимаются: `422` с `code: article_rejected` и сообщением по-русски — показать его как есть.
  В **комментариях** контакт не отклоняется, а закрывается «[контакт скрыт]» (`contact_hidden: true`).
* `listing_id` — только своё опубликованное объявление, только у тренера; иначе 422.
* Автор: тренер — полное имя из профиля, профиль открыт всегда; игрок — полное имя только при `show_profile_in_posts`, иначе имя без фамилии.
  `avatar_file_id` отдаётся только при открытом профиле. Картинки читаются обычным `GET /api/files/{file_id}`.

## Модерация
Автопроверка при отправке → статья `pending` → админ одобряет (`published`) или отклоняет (`rejected` с причиной для автора).
Админ может поставить автору «без модерации» (доверенный): тогда статьи публикуются сразу после автопроверки. Правка опубликованной
статьи недоверенным автором возвращает её на проверку (`sent_for_review: true` в ответе). Админ может снять статью (`removed`) и вернуть.
Статусы: `draft` Черновик, `pending` На проверке, `published` Опубликована, `rejected` Отклонена, `removed` Снята.

Автору приходят служебные уведомления (без переключателя): `post_review` (результат проверки) и `post_comment` (новый комментарий);
`entity_type: post`, `entity_id` — id статьи. Нажатие открывает статью.

Админка (сайт, раздел «Статьи»): `GET /api/admin/blog/posts`, `.../pending-count`, `.../posts/{id}`, `POST .../{id}/approve|reject|remove|restore`,
`POST .../comments/{id}/hide`, `GET|PUT .../authors/{id}[/trusted]`. Все действия в журнале аудита.

## Главная и лента
Оценка статьи = (3·лайки + 2·комментарии + просмотры) / (часы с публикации + 2)^1,3, окно 14 дней; лучшая по виду спорта кэшируется на час.
Нет вида спорта в профиле или нет статей по нему — случайная из лучших (стабильная в течение часа).

## Адрес статьи
`https://<сайт>/blog/{id}` — открывает статью на сайте (для «Скопировать ссылку»).
