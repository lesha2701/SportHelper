# Конфигурация

Backend читает настройки из файла `.env` в корне репозитория (или из файла, указанного в переменной окружения `ENV_FILE` — см. «Sandbox и main» ниже). Пример со всеми параметрами — в [`.env.example`](../.env.example).

Настоящие `.env`-файлы никогда не коммитятся в git (см. `.gitignore`).

## Sandbox и main

Проект запускается в двух независимых режимах из одного и того же кода:

- **sandbox** — тестовый инстанс для проверки обновлений;
- **main** — боевой бот.

У каждого режима свой файл `.env` (например, `.env.sandbox` и `.env.main`), со своим `TELEGRAM_BOT_TOKEN`, своей базой данных (или отдельной схемой) и своей корневой папкой на Яндекс.Диске. Перед запуском backend или бота укажите нужный файл:

```powershell
$env:ENV_FILE = ".env.sandbox"
.\.venv\Scripts\python -m uvicorn app.main:app
```

Если `ENV_FILE` не задан, используется `.env`. Значение `APP_MODE` (`sandbox`/`main`) попадает в логи и используется для выбора корневой папки на Яндекс.Диске (с итерации 4).

## Параметры

### Режим запуска

| Переменная | Назначение |
|---|---|
| `APP_MODE` | `sandbox` или `main`. Влияет на логи и корневую папку Яндекс.Диска. |

### Telegram Bot

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather). Используется и backend (проверка подписи `initData`), и `run_bot.py`. |
| `MINI_APP_URL` | Публичный HTTPS-адрес, на котором развёрнут frontend. Используется в кнопке `/start` бота. Для локальной разработки — адрес туннеля (ngrok и т.п.), Telegram не откроет `http://localhost`. |
| `ADMIN_TELEGRAM_IDS` | Telegram ID администраторов через запятую. Доступ к административным командам бота (`/admin`, `/stats` и т.д., начиная с итерации 13). |
| `TELEGRAM_AUTH_MAX_AGE_SECONDS` | Через сколько секунд `initData` считается устаревшим (по умолчанию сутки). |

### PostgreSQL

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения `postgresql://user:password@host:port/dbname`. |
| `DATABASE_POOL_MIN_SIZE` / `DATABASE_POOL_MAX_SIZE` | Размер пула соединений `asyncpg`. |

Миграции применяются автоматически при старте backend: если таблицы `schema_versions` ещё нет — выполняется `database/schema.sql` целиком; иначе применяются недостающие файлы из `database/patches/` по номеру в начале имени файла (`0002_*.sql`, `0003_*.sql`, …).

### JWT

| Переменная | Назначение |
|---|---|
| `JWT_SECRET` | Секрет для подписи собственных JWT (не путать с токеном бота). Обязательно замените на случайную строку в проде. |
| `JWT_ALGORITHM` | Алгоритм подписи, по умолчанию `HS256`. |
| `JWT_EXPIRES_MINUTES` | Время жизни токена в минутах. |

### CORS и HTTP-сервер

| Переменная | Назначение |
|---|---|
| `CORS_ORIGINS` | Список источников через запятую, которым разрешено обращаться к API (адрес frontend). |
| `BACKEND_HOST` / `BACKEND_PORT` | На каком адресе/порту слушает `uvicorn`. |

### Yandex AI Studio (с итерации 14)

Backend обращается к OpenAI-совместимому эндпоинту Yandex Cloud
(`{YANDEX_BASE_URL}/chat/completions`), поэтому модель адресуется как
`gpt://{YANDEX_FOLDER_ID}/{YANDEX_MODEL}/latest`.

| Переменная | Назначение |
|---|---|
| `YANDEX_API_KEY` | Ключ доступа к Yandex AI Studio. Используется только backend, не логируется. |
| `YANDEX_FOLDER_ID` | ID каталога в Yandex Cloud. |
| `YANDEX_MODEL` | Используемая модель (например `yandexgpt`, `yandexgpt-lite`). |
| `YANDEX_BASE_URL` | Базовый URL OpenAI-совместимого API (по умолчанию `https://ai.api.cloud.yandex.net/v1`). |

Если ключ не задан, все ИИ-функции возвращают понятную ошибку (`ai_unavailable`) вместо падения backend — остальное приложение работает как обычно.

### Яндекс.Диск (с итерации 4)

| Переменная | Назначение |
|---|---|
| `YANDEX_DISK_OAUTH_TOKEN` | OAuth-токен технического аккаунта. Используется только backend, никогда не передаётся frontend и не логируется. |
| `YANDEX_DISK_ROOT_FOLDER` | Корневая папка на Диске (по умолчанию `/TeamFlow`). |

Как получить `YANDEX_DISK_OAUTH_TOKEN`:

1. Зарегистрируйте OAuth-приложение на [oauth.yandex.ru](https://oauth.yandex.ru/) с доступом к **Яндекс.Диск REST API**: права `cloud_api:disk.read` и `cloud_api:disk.write` (обычный доступ к Диску, не «App Folder» — файлы хранятся в `/TeamFlow` в корне Диска, а не в изолированной папке приложения).
2. Войдите в браузере под тем Яндекс-аккаунтом, который будет техническим владельцем файлов, и откройте:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<CLIENT_ID>`
3. Подтвердите доступ — Яндекс покажет токен на экране. Токен живёт около года, `CLIENT_ID`/`CLIENT_SECRET` приложению после этого не нужны (используются только для получения токена).
4. Вставьте токен в `YANDEX_DISK_OAUTH_TOKEN`.

Без токена backend продолжает работать, но эндпоинты загрузки файлов возвращают `503 yandex_disk_not_configured`.

### Загрузка файлов (с итерации 4)

| Переменная | Назначение |
|---|---|
| `MAX_IMAGE_SIZE_MB` / `MAX_VIDEO_SIZE_MB` | Максимальный размер загружаемых файлов. |
| `UPLOAD_CHUNK_SIZE_KB` | Размер чанка при потоковой загрузке (видео не грузится в память целиком). |

### Прочие таймауты и лимиты

| Переменная | Назначение |
|---|---|
| `HTTP_CLIENT_TIMEOUT_SECONDS` | Таймаут исходящих HTTP-запросов (Яндекс.Диск, ИИ). |
| `RATE_LIMIT_PER_MINUTE` | Лимит HTTP-запросов в минуту (простой in-memory rate limiter без Redis, состояние живёт в процессе backend; с итерации 15). Ключ — авторизованный пользователь (из JWT), а не IP: за туннелем (ngrok/cloudflared) все посетители Mini App иначе делили бы один лимит на всех. IP используется только как запасной ключ для неавторизованных запросов (`POST /api/auth/telegram`). При превышении — `429` с `{"error": {"code": "rate_limited"}}`. Не действует на `/api/health` и документацию API. |

### Фоновые задачи (с итерации 10)

| Переменная | Назначение |
|---|---|
| `BACKGROUND_TASK_INTERVAL_SECONDS` | Периодичность фоновой `asyncio`-задачи (отправка уведомлений, простановка просроченных заданий, очистка файлов). Приглашения в команду отдельно не «закрываются» — они и так проверяются по `expires_at` при каждом использовании. |
| `INVITE_EXPIRATION_HOURS` | Срок действия приглашения в команду (по умолчанию 24 часа). |
| `SOFT_DELETE_RETENTION_DAYS` | Через сколько дней после мягкого удаления файлы удаляются окончательно (с Яндекс.Диска и из БД). |

### Уведомления (с итерации 10)

| Переменная | Назначение |
|---|---|
| `NOTIFICATION_MAX_ATTEMPTS` | Максимум попыток отправки уведомления, прежде чем оно помечается неудачным. |
| `NOTIFICATION_RETRY_DELAY_SECONDS` | Задержка между повторными попытками. |
| `TASK_DEADLINE_REMINDER_HOURS_BEFORE` | За сколько часов до дедлайна задания напомнить игроку (если дедлайн ближе — напоминание уходит немедленно). |

### Feature flags

| Переменная | Назначение |
|---|---|
| `FEATURE_AI_ENABLED` | Включает/выключает функции ИИ независимо от наличия ключей. |

## Frontend

Frontend настраивается отдельно через `frontend/.env.development` (для локальной разработки, коммитится — секретов не содержит) и переменные окружения сборки:

| Переменная | Назначение |
|---|---|
| `VITE_API_BASE_URL` | Адрес backend API, к которому обращается Mini App. |
