# MBA Design System — редизайн TeamFlow Sports

Дата: 2026-08-17. Статус: черновик на ревью пользователя.

## Цель

Полная пересборка визуального языка Mini App под айдентику баскетбольного
клуба МБА (Москва, Единая лига ВТБ) — не перекраска, а новая дизайн-система
(цвет, типографика, форма, орнамент) + пересмотр компоновки трёх самых
перегруженных мест интерфейса. Ощущение: «профессиональная тренировочная
система баскетбольного клуба», а не фитнес-трекер, покрашенный в красный.

Бизнес-логика, структура данных и backend **не меняются**. Изменения — это
frontend: токены, компоненты, layout, plus один новый экран (Dashboard),
целиком собранный из уже существующих API.

Референсы (только как источник стиля — логотип-графика не воспроизводится,
см. «Логотип» ниже): клубный логотип МБА (красный фон, волнообразные
розовые полосы, чёрно-белая рукописная надпись) и фотография баннера арены
(красно-белая растительная роспись, клубные цвета).

## Логотип

Файла логотипа нет и не будет использоваться — ни в исходном виде, ни как
графика, вырезанная с референс-фото. МБА — не наш бренд, это внутренний
тренировочный инструмент для клуба, а не официальный продукт лиги/клуба.
Айдентика передаётся только через цвет, шрифт, орнамент, геометрию — ровно
то, что описано в «важном принципе» исходного ТЗ («узнаётся даже без
логотипа»). Там, где сейчас в интерфейсе нет текстового брендинга — не
добавляем текстовый лейбл «МБА» намеренно, чтобы не выглядеть официальным
клубным продуктом.

## Цветовая система

### Светлая тема (основная)

```
--color-bg:              #FAFAFA
--color-surface:         #FFFFFF   /* карточки */
--color-surface-alt:     #F2F1EF   /* вложенные блоки, инпуты */
--color-border:          #E7E6E3
--color-border-strong:   #D6D4CF

--color-graphite:            #17181B   /* текст, тёмные блоки */
--color-graphite-elevated:   #1F2024   /* тёмные карточки на светлом фоне */

--color-text:            #17181B
--color-text-secondary:  #5C5E66
--color-text-tertiary:   #96979E

--color-primary:         #D91E2B   /* MBA Red */
--color-primary-hover:   #B8121E
--color-primary-text:    #FFFFFF
--color-primary-tint:    #FBEAE9   /* светлая красная заливка (бывший primary-glow) */

--color-coral:           #F2A6A0   /* вторичный акцент — бейджи, second-tier */
--color-blush:           #FBEAE9   /* самый светлый розовый — фоновые заливки */

--color-success:         #1F9D5C   /* без изменений — нейтрален к бренду */
--color-success-bg:      #EAFAF1
--color-danger:          #E85D2A   /* ошибки — оранжево-красный, НЕ MBA Red */
--color-danger-bg:       #FDF0E9
--color-warning:         #B6790F
--color-warning-bg:      #FDF3E0
```

### Тёмная тема (вторичная, полноценная — не заглушка)

```
--color-bg:              #121214
--color-surface:         #1C1D20
--color-surface-alt:     #26272B
--color-border:          rgba(255,255,255,0.08)
--color-border-strong:   rgba(255,255,255,0.14)

--color-text:            #F2F1EF
--color-text-secondary:  #A8A9AE
--color-text-tertiary:   #6E6F75

--color-primary:         #FF3B3F   /* чуть ярче для контраста на тёмном */
--color-primary-hover:   #FF5A5D
--color-primary-tint:    rgba(255,59,63,0.14)

--color-coral:           #E8918C
--color-success/-danger/-warning: те же оттенки, что в светлой (нейтральны к теме)
```

Переключатель тем (`ThemeToggle.tsx`) остаётся, поведение не меняется —
только палитра под обеими темами.

### Правило иерархии красного

Красный = primary CTA, активные элементы навигации/табов, ключевые
KPI-цифры, акцентные полосы. Красный **не** заливает целые экраны и не
используется для декора ради декора. Ошибки — отдельный оттенок
(`--color-danger`, оранжево-красный), чтобы не путаться с брендом. Coral —
только вторичные акценты (бейджи низкого приоритета, декоративные заливки),
никогда не CTA.

## Типографика

Пара шрифтов не меняется: **Barlow Condensed** (display — заголовки, табы,
навигация, крупные цифры) + **Montserrat** (весь читаемый текст). Оба уже
подключены, полностью поддерживают кириллицу.

Изменения масштаба/веса:
- Hero-KPI цифры (Dashboard, статистика): `56–72px`, вес `800`,
  `font-variant-numeric: tabular-nums`.
- `.pageHeading`: `28px/800` (было `24px/800`).
- Все числовые показатели в интерфейсе (счёт, посещаемость, показатели
  игрока) получают `tabular-nums` — сейчас этого нет, из-за чего цифры
  «прыгают» по ширине при обновлении.
- Uppercase — только для структурных подписей (навигация, табы, лейблы
  секций), не для пользовательских данных (имена, названия команд) — это
  правило уже есть в текущей системе, сохраняется без изменений.

## Форма и геометрия

- Радиусы уменьшаются и становятся более «чёткими»:
  `--radius-sm: 4px`, `--radius-md: 8px`, `--radius-lg: 12px`,
  `--radius-pill: 999px` (только бейджи/теги/аватары-инициалы).
- Карточки — прямоугольная, чёткая геометрия. «Асимметричный» характер,
  упомянутый в ТЗ, достигается не переменным радиусом по карточкам (это
  хрупко масштабировать на 50 экранов и легко скатывается в визуальный
  шум), а графическими приёмами: акцентная полоса/уголок цвета
  `--color-primary` на ключевых карточках, диагональный срез в hero-блоках,
  орнаментальные полосы (см. ниже) как разделители. Это системный приём,
  а не ручная доводка каждой карточки.
- Ключевые карточки (Dashboard hero, KPI на статистике, карточка
  «следующее событие») могут быть полностью тёмными
  (`--color-graphite-elevated`) с красным акцентом — независимо от
  активной темы приложения (светлой/тёмной), это часть композиции, а не
  темы.
- Прогресс-бары — тонкие, с прямыми (не pill) торцами, заливка
  `--color-primary` на треке `--color-surface-alt` — отличает их от
  типичных «фитнес-трекерных» скруглённых полосок.

## Орнамент

Мотив — волнообразные диагональные полосы разной толщины (по референсу
логотипа), переработанные в сдержанный digital-паттерн. Новый shared
SVG-компонент `components/shared/Ornament.tsx` (по аналогии с уже
существующими `Icon.tsx`/`illustrations.tsx`):

```tsx
<Ornament tone="primary" | "graphite" | "blush" intensity="subtle" | "bold" />
```

- `subtle` (opacity ~0.06–0.10) — фон hero-блоков, карточек статистики,
  пустых/ошибочных состояний. Никогда не за текстом с плотными данными
  (списки, таблицы, формы) — только за заголовочными/декоративными зонами.
- `bold` (полная непрозрачность полос, но ограниченная область — например
  полоса высотой 8–12px) — тонкие декоративные разделители между секциями,
  верх онбординга.
- Никогда не на весь экран, никогда не за интерактивными элементами
  (кнопки/инпуты не перекрываются паттерном).

## Компоненты — системные правила

Правила ниже определяют пересборку, конкретная разметка каждого компонента
уточняется на этапе реализации (это не решение, требующее отдельного
согласования по каждому пункту):

- **Кнопки** — primary: заливка `--color-primary`, белый текст, без
  градиента, `--radius-md`. Secondary: контур `--color-graphite`/текст.
  Tertiary: текст без фона. Нажатие — `scale(0.97)` (тактильная обратная
  связь уже есть в системе, сохраняется).
- **Карточки** — см. «Форма и геометрия» выше.
- **Табы** — там, где остаются (Библиотека: Упражнения/Планы/Шаблоны;
  Статистика: команда/игрок) — подчёркивание активного таба красным, не
  заливка pill (текущий паттерн, сохраняется).
- **Нижняя навигация** — активный пункт: красная иконка/подпись + тонкая
  красная полоса-индикатор сверху, на белом фоне бара.
- **Бейджи/теги** — pill, цвет по смыслу: красный только для «главный/
  срочный» статус, coral — второстепенный, графит — нейтральный, оранжевый
  (`--color-danger`) — просрочено/ошибка.
- **Прогресс-индикаторы** — см. «Форма и геометрия».
- **KPI/статистика** — новый shared-компонент `StatTile`/`KpiNumber`:
  крупная tabular-nums цифра + мелкий uppercase-лейбл, опционально —
  тонкая красная мини-полоса под цифрой. Заменяет текущий `.statGrid`/
  `.statValue` с сохранением их роли (реальные показатели из API, не
  выдуманные метрики — правило из текущей системы остаётся).
- **Графики** — минимализм: спарклайны/простые сравнения периодов, красная
  основная серия, графитовая вторичная, без тяжёлых сеток. Решается на
  этапе реализации конкретного графика с dataviz-скиллом, здесь фиксируется
  только характер (минимализм, 1-2 цвета, без визуального шума).
- **Инпуты/дропдауны** — прямоугольные, hairline-бордер, красный
  бордер+ring на фокусе (замена текущего синего), лейбл над полем.
- **Модальные окна** — без изменений в поведении, обновляются токены и
  геометрия по общим правилам.
- **Пустые/ошибочные/загрузочные состояния** — три существующие
  SVG-иллюстрации (`illustrations.tsx`) перерисовываются в новой линии
  (красный вместо синего `currentColor`), фон — `Ornament tone="blush"
  intensity="subtle"`.
- **Карточки тренировки/упражнения/профиля спортсмена** — используют новую
  геометрию/цвет + `StatTile` там, где уже есть числовые показатели;
  структура полей не меняется.

## Layout / IA — три перегруженные точки

Общий принцип: progressive disclosure. Экран показывает по умолчанию
только необходимое для основного сценария; второстепенное скрыто за
раскрытием. Функциональность и структура данных не меняются — это
перекомпоновка существующего.

**1. Формы создания (тренировка/задание/план).** Плоский список полей →
секции по паттерну `.fieldSectionLabel` (уже есть, сейчас используется
только в `PlayerProfileForm`) с раскрытием: обязательный минимум для
сценария открыт всегда; необязательное (упражнения/план/показатель/
дедлайн для задания; повторяемость/тип для тренировки) — свёрнуто в
подписанные секции, раскрывается по тапу. Валидация и порядок полей в
данных — без изменений.

**2. Экран команды.** Горизонтальный таб-бар (Обзор/Тренировки/Задания/
Матчи + строки-ссылки на Состав/Статистику/Настройки внутри Обзора) →
Обзор становится хабом: карточки-разделы (Состав, Тренировки, Задания,
Матчи, Статистика, Настройки), каждая — крупная тайл-карточка с иконкой,
коротким статусом («3 тренировки на неделе», «2 задания на проверке») и
переходом по тапу. Табов не остаётся — один сценарий «зашёл в команду →
вижу, что внутри → тапнул нужное». Списки/детали, которые раньше жили под
табами (`TeamTrainingsTab`/`TeamTasksTab`/`TeamMatchesTab` и т.д.), никуда
не деваются — это те же экраны, просто открываются тапом по тайлу вместо
таба, и `← Назад` с них ведёт обратно на хаб (Обзор), а не выше по стеку.

**3. Навигация в целом.** Новый Dashboard («Главная») — входная точка,
снимает «непонятно, с чего начать». Нижняя навигация: тренер — Главная /
Команды / Библиотека / Календарь / Профиль (5); игрок — Главная / Команды
/ Календарь / Профиль (4). Внутри разделов — единый паттерн «заголовок +
← Назад», без вложенной табуляции глубже одного уровня (кроме самого
экрана команды, который теперь и есть тот единственный уровень).

## Dashboard — новый экран

Собирается полностью из существующих эндпоинтов, без изменений backend:

1. **Hero-заголовок** — приветствие, роль, дата; `Ornament` фон
   (`subtle`, tone по теме).
2. **Ближайшее событие** — из `GET /api/calendar` (уже агрегирует
   тренировки/матчи/дедлайны с правами доступа) — самое близкое предстоящее
   событие крупной карточкой, тап открывает существующий экран деталей.
3. **KPI-ряд**:
   - Игрок: из `GET /api/players/{user_id}/stats` — посещаемость, серия
     посещений, задания (выполнено/просрочено), последний показатель.
   - Тренер: из `GET /api/teams/{id}/stats` для **текущей выбранной
     команды**. Если команд несколько — компактный переключатель-чипы
     сверху ряда (просто повторный вызов того же эндпоинта с другим
     `team_id`, без нового backend-агрегата). Явное ограничение: сводного
     KPI «по всем командам сразу» нет и не будет — в backend нет такого
     агрегата, а придумывать его — это уже не редизайн, а новая фича.
4. **Недавняя активность** — последние прошедшие тренировки/матчи, тот же
   `GET /api/calendar` с `date_from` в прошлом (эндпоинт уже это умеет).
5. **Рекомендации** — карточка-переход к уже существующим ИИ-функциям
   (`PlayerStatsScreen`/`TeamStatsTab`), а не встроенный живой ИИ-контент:
   вызывать ИИ автоматически при каждом открытии Dashboard — это лишние
   платные вызовы Yandex AI Studio при каждом заходе в приложение, эндпоинты
   и так спроектированы как «по кнопке». Карточка просто ведёт туда, где
   рекомендации уже можно запросить.
6. **Быстрые действия** — тренер: «+ Тренировка», «+ Задание»; игрок: «Мои
   задания» (внутри команды), «Календарь».

**Пустое состояние** (ни одной команды): не сетка нулевых KPI, а
онбординг-ориентированный экран — «Создайте команду» / «Вступите по
приглашению», в стиле существующих `StateScreen`/illustrations.

## Технический подход

Вариант C из обсуждения — гибрид: основной механизм ретрайминга остаётся
текущим (CSS-модули + расшаренные классы в `index.css` + 7
`*.module.css`, которые уже управляют ~50 экранами централизованно).
Новое — 2-3 лёгких shared-компонента там, где нужна принципиально новая
графика:
- `components/shared/Ornament.tsx` — орнамент.
- `components/shared/StatTile.tsx` (или расширение существующего
  `.statGrid` паттерна) — крупные KPI-цифры.
- Новый экран `components/dashboard/DashboardScreen.tsx` +
  `dashboard.module.css`.

`frontend/design-system/teamflow-sports/MASTER.md` обновляется как единый
источник правды по итогам редизайна (аналогично тому, как он уже
обновлялся 2026-07-18).

## Порядок выкатки

1. **Ядро на одобрение**: токены (`index.css`, обе темы), геометрия,
   `Ornament`, `StatTile`, кнопки/карточки/бейджи/прогресс/навигация/табы,
   и новый `DashboardScreen` целиком — показывается в браузере на
   dev-стенде (`docker-compose.dev.yml`, уже настроен). Пользователь
   смотрит вживую и подтверждает направление.
2. **Экран команды** — переход на хаб-карточки (пункт 2 из Layout/IA).
3. **Формы создания** — секционирование (пункт 1 из Layout/IA).
4. **Остальные ~45 экранов** — механический раскат тех же токенов/классов
   (Teams/Library/Trainings/Tasks/Matches/Calendar/Stats/Profile и все
   формы/детали внутри них), без структурных изменений сверх уже описанных
   трёх точек.
5. **Проверка mobile/responsive** — на реальном экране Mini App (dev-стенд
   уже открывается в браузере по `http://localhost:5175`).

## Явно вне рамок этого редизайна

- Изменения backend/схемы БД/API — ноль.
- Новые бизнес-функции (кроме визуальной сборки Dashboard из существующих
  данных).
- Кросс-командная агрегация статистики тренера (см. «Dashboard», KPI-ряд).
- Логотип-графика МБА как ассет в продукте.
- Изменение UX-логики форм/переходов там, где это не входит в три
  зафиксированные точки (формы создания, экран команды, навигация).
