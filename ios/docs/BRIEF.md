# Задание: iOS-приложение SportArenaGlobal (отдельный репозиторий)

Этот документ — самодостаточное техническое задание для ассистента (или разработчика), который начинает iOS-приложение **с нуля в отдельном репозитории**. Читайте целиком, затем начните с раздела «Что делать прямо сейчас».
Рядом лежит `openapi-mobile.json` — машиночитаемый контракт сервера (198 операций, без административных). Скопируйте оба файла в новый репозиторий в папку `docs/`.

Язык общения с владельцем проекта — **русский**.

---

## 1. Что это за проект

**SportArenaGlobal** — платформа для тренеров и игроков (спортивные команды и личные тренировки). Сейчас это веб-сайт `https://sportarenaglobal.ru` (React + FastAPI + PostgreSQL). Задача — **нативное iOS-приложение**, которое работает с тем же сервером. Android делает другой человек параллельно, отдельным приложением; общего кода нет, общий только сервер и контракт API.

Роли (выбираются при регистрации и дальше не меняются):
- **Игрок (player)** — состоит в командах, смотрит календарь и тренировки, записывается к тренерам, оплачивает личные тренировки, общается в чатах.
- **Тренер (coach)** — создаёт команды и тренировки, ведёт объявления для личных тренировок, подтверждает заявки, видит финансы и выводит деньги, общается в чатах.
- (Администраторы работают только в веб-панели — в приложении их функций нет.)

## 2. Границы первой версии (MVP)

Входит:
1. Регистрация, подтверждение почты, вход, выход, восстановление пароля, удаление аккаунта.
2. Профиль игрока/тренера (просмотр и редактирование), аватар.
3. Календарь и тренировки: список, детали, для тренера — создание/редактирование.
4. Каталог тренеров и объявления; запись на личную тренировку; «Мои брони» (игрок) и «Записи»/«Входящие заявки» (тренер).
5. **Оплата** подтверждённой брони через ЮKassa (см. раздел 5).
6. **Чаты**: личной тренировки и команды (текст, фото, видео).
7. Уведомления (колокольчик внутри приложения + push, когда сервер их получит).
8. Команды: список, состав, вход по приглашению.

Второй волной (не в MVP): финансы тренера и вывод средств, библиотека упражнений и планы, ИИ-функции, статистика, задания, матчи.

## 3. Как приложение разговаривает с сервером

**Базовый адрес:** `https://sportarenaglobal.ru` (все маршруты под `/api`). Тестовый сервер владелец должен предоставить отдельно (см. раздел 7); пока можно поднять сервер локально из репозитория бэкенда.

**Формат:** JSON, `snake_case`. Идентификаторы — UUID (строки). Деньги в финансовых методах — **целые копейки**; цены объявлений/броней — числа в рублях (`price_per_session`). Даты — ISO 8601; время броней приходит в UTC, на сайте его показывают как UTC — уточните у владельца, показывать ли локальное время.

**Ошибки** всегда одной формы:
```json
{ "error": { "code": "invalid_password", "message": "Неверный пароль.", "field": "password", "retry_after": 30 } }
```
`message` — готовый русский текст для показа человеку; `field` — поле формы (может отсутствовать); `retry_after` — секунды ожидания при 429. Показывайте `message` как есть, логику строите по `code`. 401 — сессия закончилась (выйти на экран входа), 403 с кодом `csrf_failed` — нет/устарел CSRF-токен.

**Вход и сессия (важно):** сервер сейчас использует **cookie-сессию**:
1. `POST /api/auth/login` `{email, password}` → в ответе пользователь и `csrf_token`; сама сессия приходит в `Set-Cookie` (HttpOnly, 30 дней; имя `__Host-sag_session`).
2. `URLSession` с общим `HTTPCookieStorage` сохраняет и отправляет cookie сам. **Каждый изменяющий запрос (POST/PUT/PATCH/DELETE) обязан нести заголовок `X-CSRF-Token: <csrf_token>`**; токен берётся из ответа `login` или `GET /api/auth/me` (его нужно получать заново при старте приложения и хранить только в памяти).
3. Выход — `POST /api/auth/logout`; «выйти на всех устройствах» — `/api/auth/logout-all`; список сессий — `GET /api/auth/sessions`.
4. В коде сервера есть режим Bearer-токена (`BEARER_AUTH_ENABLED`), но он выключен, и токен в теле ответа сейчас не возвращается. **Начинайте с cookie + CSRF** — это работает без изменений сервера. Отдельный вход по токену — запрос владельцу бэкенда (раздел 7).
5. Регистрация: `POST /api/auth/register` → письмо со ссылкой → `POST /api/auth/verify-email` (токен из ссылки + пароль) — **подтверждение почты уже открывает сессию**, отдельный вход не нужен. Ссылка из письма ведёт на сайт; чтобы она открывалась в приложении, нужны универсальные ссылки (раздел 7), до тех пор пользователь подтверждает почту в браузере и затем входит в приложении.
6. Если у аккаунта включена двухфакторная защита, после входа нужно `POST /api/auth/mfa/verify`. Для обычных игроков и тренеров MFA не требуется, поддержку можно отложить.
7. Лимиты запросов: вход, регистрация, отправка сообщений и пр. ограничены; при 429 покажите `message` и подождите `retry_after`.

**Файлы:** загрузка — `multipart/form-data` с полем `file`. Фото: JPEG/PNG/WebP/GIF, до **10 МБ** (сервер сам уменьшает и конвертирует в WebP). Видео: MP4/MOV/WEBM, до **100 МБ** и **60 секунд**. Скачивание — `GET /api/files/{id}` (нужна сессия; `?size=thumb` — миниатюра). Файлы требуют cookie, поэтому картинки загружайте тем же `URLSession`, а не напрямую из `AsyncImage`.

**Список возможностей сервера:** `GET /api/features` (без входа) — какие функции включены (`payments`, `trainer_balance`, `trainer_withdrawals`, `telegram`). Скрывайте интерфейс выключенных функций.

## 4. Карта API для MVP

Полный список — в `openapi-mobile.json`. Основные группы (тег → смысл):

| Тег | Для чего |
|---|---|
| `auth` | регистрация, вход, подтверждение почты, пароль, сессии, удаление аккаунта (`/account/delete`) |
| `profile`, `onboarding` | профили игрока/тренера, режим, онбординг |
| `profile_media`, `files` | галерея, аватар, скачивание файлов |
| `teams`, `invites` | команды, состав, приглашения и заявки на вступление |
| `trainings`, `calendar`, `reports` | тренировки, календарь, отчёты о тренировках |
| `coach-listings`, `coaches`, `players` | объявления тренеров, каталог, публичные профили |
| `bookings` | заявки на личные тренировки, подтверждение, оплата, «Мои брони» |
| `payments` | вебхук ЮKassa (приложению не нужен), оплата — через `bookings` |
| `chat` | чаты личной тренировки и команды |
| `notifications` | колокольчик, настройки |
| `finance` | баланс и выводы тренера (вторая волна) |

Состояния, которые нужно знать:
- **Бронь** `status`: `pending` → `confirmed` | `declined` | `expired`; `cancelled`.
- **Оплата брони** `payment_status`: `not_required`, `unpaid`, `processing`, `paid`, `canceled`, `refund_pending`, `refunded`.
- Кнопка «Оплатить» показывается только для `confirmed` + `unpaid`/`canceled` (и только если `features.payments`).

## 5. Ключевые сценарии (последовательности запросов)

**Бронирование и оплата**
1. Игрок: `GET /api/coach-listings/{id}/slots?from_date&to_date` → `POST /api/bookings` `{listing_id, starts_at, format}`.
2. Тренер: `GET /api/bookings/coach/pending` → `POST /api/bookings/{id}/confirm`.
3. Игрок: `POST /api/bookings/{id}/pay` → `{confirmation_url}`. Откройте ссылку в **`SFSafariViewController`** (или `ASWebAuthenticationSession`) — не в `WKWebView`. Карточные данные вводятся на странице ЮKassa, приложение их не видит.
4. После оплаты ЮKassa возвращает на `https://sportarenaglobal.ru/payments/return?booking=<id>`. Приложение **ничему не верит из адреса**: на возврате (или при закрытии браузера) вызывайте `POST /api/bookings/{id}/payment/sync` и показывайте только то, что ответил сервер (`payment_status`). Пока статус `processing` — опрашивайте раз в 3 секунды не более 10 раз.
5. Правила App Store: личная тренировка с тренером — **услуга вне приложения**, внешняя оплата допустима (гайдлайн 3.1.3(e)); это нужно прямо написать в «Notes for Review».

**Чат** (`/api/chats`)
- Открыть: `GET /api/chats/for-booking/{booking_id}` (после оплаты) или `/for-team/{team_id}`.
- Сообщения: `GET /{id}/messages` (последние 30), `?after_id=N` — только новое (опрашивайте каждые ~5 секунд, пока экран открыт), `?before_id=N` — более старые.
- Отправка: `POST /{id}/messages` `{body, client_key}`; **`client_key` — UUID, создаётся один раз на сообщение и повторяется при повторной отправке** (так двойное нажатие или повтор после обрыва не создают дубль). Вложение: `POST /{id}/messages/media` (multipart: `file`, `client_key`, необязательный `body`).
- Прочитано: `POST /{id}/read` `{up_to_id}`; непрочитанные счётчики: `GET /api/chats/unread`.

**Уведомления:** `GET /api/notifications` (список), `POST /{id}/read`, `/read-all`, настройки — `/preferences`. У каждого уведомления есть `category` и `entity_id`: по ним открывается нужный экран (`booking_requested`/`booking_decided` → брони, `chat_booking` → чат брони, `chat_team` → чат команды, `payment_update`, `new_training` и т. д.).

## 6. Рекомендуемая архитектура

- **iOS 17+**, SwiftUI, Swift 5.10+/6, `async/await`, Observation (`@Observable`).
- Слои: `Networking` (клиент + CSRF + обработка 401/429) → `Repositories` → `ViewModels` → `Views`. Без сторонних зависимостей, где можно обойтись; допустимы swift-openapi-generator (по `openapi-mobile.json`), KeychainAccess не нужен — достаточно Security framework.
- Клиент API лучше **генерировать** из `openapi-mobile.json` (Apple `swift-openapi-generator` + `URLSession`-транспорт), а CSRF и cookie добавить middleware. Если генерация даст неудобные модели — написать ручной клиент для MVP-эндпоинтов, а контракт использовать как справочник.
- Навигация: `TabView` — Главная, Команды, Календарь, Тренеры, Профиль (как на сайте); у тренера и игрока набор вкладок немного отличается — смотрите сайт.
- Состояние авторизации — один `AuthStore`; при 401 — сброс и экран входа.
- Локализация: интерфейс на **русском**, строки сразу выносить в `Localizable.xcstrings`.
- Тёмная и светлая тема обязательны (на сайте обе).
- **Дизайн:** повторять сайт. Основной цвет `#d91e2b` (светлая тема) / `#ff3b3f` (тёмная); фон `#fafafa` / `#121214`; поверхность `#ffffff` / `#1c1d20`; заголовки — шрифт **Oswald** (заглавные, с разрядкой), текст — **Montserrat**. Логотип и иллюстрации берите из репозитория сайта (`frontend/src/assets`, `frontend/design-system`), владелец выдаст.
- Тесты: unit-тесты репозиториев и ViewModel на заглушке сети; UI-тесты ключевых сценариев (вход, бронь, чат).

## 7. Чего на сервере ещё нет (запросите у владельца; в iOS-репозитории этого не сделать)

Оформляйте как короткие запросы владельцу бэкенд-репозитория, не обходите их хитростями:
1. ~~**Push-уведомления (APNs)**~~ Сделано на сервере: `PUT /api/devices`, `POST /api/devices/remove`, отправка из фоновой задачи — см. docs/push.md. Опрос `GET /api/notifications` остаётся.
2. **Вход по токену** (вместо cookie) — по желанию, если cookie-схема окажется неудобной.
3. **Жалобы на сообщения и блокировка пользователя в чате** — обязательны для App Store (гайдлайн 1.2, контент пользователей). Без них нельзя отправлять приложение на ревью. Удаление аккаунта уже есть (`/api/auth/account/delete`) — оно должно быть доступно из экрана профиля (гайдлайн 5.1.1).
4. **Универсальные ссылки:** файл `apple-app-site-association` на сайте — чтобы ссылки из писем (подтверждение почты, сброс пароля) и возврат из оплаты открывались в приложении.
5. ~~**Версия API и «минимальная версия приложения»**~~ — **сделано** (карточка #28): `GET /api/app-config`, заголовки `X-Client-Platform`/`X-Client-Version`, ответ `426 client_update_required`; приложение шлёт заголовки в каждом запросе, при запуске спрашивает `app-config` и показывает экран «Нужно обновить приложение» (обязательное обновление) или баннер «Вышла новая версия» (предложение). Контракт — `docs/mobile.md`.
6. **Тестовый сервер и тестовые аккаунты** (с имитацией ЮKassa, без реальных денег) для вас, Android-разработчика и проверяющих Apple.

Пока этого нет, не блокируйтесь: стройте экраны на том, что есть.

## 9. Требования App Store, о которых легко забыть

- Приложение — не обёртка сайта (гайдлайн 4.2): все экраны нативные.
- Чат и фото пользователей → жалобы, блокировка, быстрая реакция (1.2).
- Удаление аккаунта из приложения (5.1.1(v)).
- Вход только по почте и паролю, значит «Вход через Apple» не требуется; если когда-нибудь появится вход через соцсети — понадобится (4.8).
- `Info.plist`: тексты запросов доступа к фото/камере/микрофону (отправка фото и видео в чат); `PrivacyInfo.xcprivacy` с перечнем собираемых данных.
- ATT (отслеживание) не нужен, если нет рекламной аналитики.
- Деньги: тренеры получают оплату от платформы, а не через покупки в приложении; в описании не использовать слова «подписка»/«премиум», которых нет.

## 10. Правила работы с владельцем

- Отвечать по-русски. Планы и итоги — коротко и по пунктам.
- **Не пушить в репозиторий и не публиковать сборки без явного разрешения** владельца в этом сообщении; коммитить локально и спрашивать.
- **Никаких секретов** в репозитории и в чате: ключи, пароли, токены, сертификаты — только в Keychain/CI-секретах. В исходниках — адрес тестового сервера и публичные настройки.
- **Никаких реальных платежей** при разработке: оплату проверять только на тестовом сервере с имитацией ЮKassa.
- Менять контракт сервера нельзя: если API неудобен или чего-то не хватает — составить запрос по разделу 7.
